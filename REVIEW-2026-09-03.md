## Stage 1 — Orientation

### Purpose, inferred from the code alone

Reads a Medidata Rave-style "clinical view" CSV extract and maps it to 14 SDTM domains,
4 ADaM datasets and a define.xml stub, with everything study-specific held in a single
`study_spec` object rather than in code. Ships a seeded synthetic extract generator so
the whole EDC to SDTM to ADaM chain runs, self-validates and regression-tests with no
live EDC and no network.

### Public API surface — 54 exports plus one S3 method

| Role | Exports |
|---|---|
| Ingestion | `read_clinical_view`, `read_rave_extract`, `read_cv_metadata`, `read_codelists`, `label_from_cv_metadata`, `col_or_na`, `rave_header_cols` |
| Spec | `new_study_spec`, `ct_lookup`, `spec_synth01`, `spec_synth02`, `print.study_spec` |
| SDTM mappers | `map_dm/ex/vs/ae/cm/ds/sv/lb/mh/suppdm/suppae/suppex/co/relrec`, `subject_ref` |
| ADaM | `derive_adsl`, `derive_adae`, `derive_advs`, `derive_adlb` |
| Date & derivation helpers | `rave_dtc`, `dtc_date`, `impute_dtc`, `min_dtc`, `max_dtc`, `compute_age`, `derive_dy`, `derive_dy_d`, `derive_seq`, `check_ct` |
| Format & unit helpers | `yn`, `clean_verbatim`, `apply_labels`, `to_standard`, `standard_unit`, `resolve_standard` |
| Structure assembly | `make_supp`, `make_relrec` |
| Validation | `validate_sdtm`, `validate_adam`, `stop_on_error` |
| Output & orchestration | `write_sdtm`, `build_define_xml`, `build_all` |
| Generator | `generate_rave_extract` |

### Internal architecture

`build_all()` is the only run-order authority:

```
extract dir
  -> read_rave_extract()      all-character, EOF-marker truncation guard,
                              RecordActive filter, CV-metadata labels
  -> map_dm()                 FIRST: its subject_ref() (USUBJID/RFSTDTC/RFENDTC)
                              anchors every other domain's --DY
  -> the other 13 mappers     spec-driven via map_variables() where the domain is a
                              row-per-variable map; hand-written pivots for VS/LB;
                              SUPP/CO/RELREC join back on AESPID/CMSPID/VISITNUM
  -> validate_sdtm() + stop_on_error()
  -> derive_adsl() -> derive_adae()/advs()/adlb()
  -> validate_adam() + stop_on_error()
  -> write_sdtm() (RDS + XPT v5) + build_define_xml()
```

Nothing is written until both validators pass.

Four abstractions carry the design:

1. **`study_spec`** — 11 tibbles (`study`, `sites`, `arms`, `visits`, `codelists`,
   `supp`, `units`, `forms`, `tests`, `bds`, `variables`).
2. **A fixed 12-name transform vocabulary** plus a **derivation registry**
   (`.derivations`, 17 named `function(data, spec)` entries).
3. **`map_variables()`** (`engine.R`, internal) — evaluates spec rows *in table order*,
   so later rows see columns created by earlier ones. That ordering is load-bearing and
   unenforced.
4. **The issue tibble** (`domain`/`severity`/`check`/`detail`) plus `stop_on_error()`
   as the pipeline guard.

**No S7 anywhere.** `study_spec` is a plain S3 list with a validating constructor and one
`print` method. Worth a deliberate decision rather than drift — though the
constructor-validates-then-`class<-` pattern is doing S7's job adequately here, so this is
a "would have done differently", not a defect.

**Where state and config live:** package-level constants only (`.derivations`,
`.transforms`, `.sdtm_req_static`, and the generator's `.SITES`/`.FOLDERS`/`.CODELISTS`),
plus `utils::globalVariables()`. No package options, no environments. The one genuinely
mutable global touched is the RNG — see finding 10.

### What could not be determined from the code

This is the most useful part of the stage. Each of these changes what "correct" means
somewhere in Stage 2.

1. **Product or portfolio piece?** README says "grew out of a script-based training
   project"; DESCRIPTION, 5-platform CI, NEWS and CRAN polish say product. *Undecided.*
2. **Is Rave the contract, or is "EDC" the contract?** Everything internal says Rave
   (RWS timeout, `_RAW`/`_DECODE`/`_STD` suffix families, the 30-column header block);
   the package name and docs say EDC generally.
3. **Is `RFENDTC <- RFXENDTC` deliberate?** The spec renames last-dose date into RFENDTC
   and puts end-of-participation in RFPENDTC. Sponsor convention or oversight?
4. **Should the TRTEMFL window be spec-configurable?** ADVS reference ranges moved into
   `spec$bds` in 0.2.0; the treatment-emergent window stayed hardcoded, in two places.
5. **Is `RELTYPE` on record-level RELREC intentional?** See finding 14.
6. **Is SV-from-`RecordDate` a property of this EDC build or of these two synthetic
   studies?** The data-entry date is currently being used as the visit date.
7. **What is `data/` for?** Gitignored *and* `.Rbuildignore`d, but holds
   committed-looking XPT/RDS/define.xml. Package data, or scratch output?
8. **Where should validator thresholds live?** Age 18-100 is hardcoded; ADVS ranges are
   in the spec. Inconsistent on purpose?
9. **Is `AGE` deliberately anchored differently for treated (first dose) versus screen
   failures (consent)?** The derivation comment says yes — worth confirming, because it
   makes AGE non-comparable across the two groups.
10. **Are the frozen reference `.rds` files a permanent contract or a bridge from the
    retired script pipeline?** As written they lock in current behaviour, bugs included.
11. **Is `map_variables()` meant to stay internal?** It has a full `.Rd`, is
    `@keywords internal`, and `test-spec.R` calls it directly.

## Stage 2 — Triage

### (a) Correctness / silent wrong answers

#### 1. TRTEMFL is silently `""` when TRTEDT is missing

`R/adam-adae.R:89-93`

```r
TRTEMFL = case_when(
  is.na(ASTDT) | is.na(TRTSDT)               ~ "",
  ASTDT >= TRTSDT & ASTDT <= TRTEDT          ~ "Y",
  .default                                   ~ ""
)
```

`TRTEDT` is NA for any dosed subject whose last EX record has no end date — ongoing at
data cut, blank `EXENDAT`, or a partial date `impute_dtc()` could not resolve.
`TRUE & NA` is NA, `case_when` falls through to `.default`, and **every AE for that
subject gets `TRTEMFL = ""`**. That understates the count in the single most consequential
table in a safety package, with no error and no warning.

Smallest fix:

```diff
-      ASTDT >= TRTSDT & ASTDT <= TRTEDT          ~ "Y",
+      ASTDT >= TRTSDT &
+        (is.na(TRTEDT) | ASTDT <= TRTEDT)        ~ "Y",
```

The same edit is needed at `validate-adam.R:298` — which is the problem, see next.

#### 2. The ADaM validator re-implements the derivations instead of checking them

`R/validate-adam.R:296-300` is a character-for-character copy of `adam-adae.R:89-93`.
Likewise `:114` copies `adam-adsl.R:99` (TRTDURD), `:324` copies `adam-adae.R:86` (ASTDY),
and `:471-472` copy `adam-advs.R:79-84` (CHG/PCHG).

The roxygen claims it "recomputes the derivations from their inputs instead of trusting
the build". What it actually detects is *post-hoc corruption of the built dataset* —
which is exactly what the meta-tests in `test-validators.R` inject, which is why they
pass. It cannot detect a wrong rule, and finding 1 is invisible for precisely this reason.

This is systemic, not local: it is the mechanism that lets findings 1, 3 and 7 survive a
green suite. Two ways out, and either is fine:

- narrow the documented claim to what it does, or
- express each rule once in a function both the deriver and the validator call, and test
  the rule itself against hand-built inputs.

For a package positioned as an admiral alternative, the second is worth the work — "it
validates its own derivations" is a large part of what such a package is selling.

#### 3. `compute_age()` is off by one, always low, on roughly 1 subject in 2,000

`R/helpers-derive.R:18`

```r
age <- as.integer(floor(as.numeric(difftime(refdt, brthdt, units = "days")) / 365.25))
```

Verified: `compute_age(as.Date("2003-01-01"), as.Date("2024-01-01"))` returns **20**.
The subject is 21. Sweeping 1940-2008 birthdates against three reference dates gives a
0.05% mismatch rate, every one in the same direction (understated).

It reaches `DM.AGE`, `ADSL.AGE` and every age subgroup. The concrete failure mode:
someone who turns 18 on their consent date can come back as 17 and trip
`validate_adam()`'s `AGE < 18` **ERROR**, which stops the whole build with a message that
points at the data rather than at the arithmetic.

Fix with anniversary arithmetic, or `clock::date_count_between(b, r, "year")`.
The two existing tests (1990-06-15 against 2024-06-14 and 2024-06-15) happen to land on a
pair the approximation gets right.

#### 4. `build_define_xml()` never attaches the ValueListRef — a stray `]` in the XPath

`R/define-xml.R:258`

```diff
-    xpath <- str_c("//ItemGroupDef[@Name=']", d,
+    xpath <- str_c("//ItemGroupDef[@Name='", d,
                    "']/ItemRef[@ItemOID='IT.", d, ".", f$var, "']")
```

The bracket sits *inside* the quote, so the query searches for `@Name=']VS'`.
`xml_find_first()` returns `xml_missing`; `xml_add_child()` on `xml_missing` is a silent
no-op — no error, no warning. The value-level metadata is emitted and then orphaned.

Evidence, since this could not be executed here:

- `git log -S"@Name=']" -- R/define-xml.R` puts the character in **b3e0f28**
  ("CI (R-CMD-check, coverage, lint) + locale-independent generator"), i.e. a stray
  keystroke during an unrelated edit.
- The committed `data/sdtm/define.xml` (written 13:24) predates that source edit (15:35)
  and still contains both `<def:ValueListRef>` elements — the before/after proof.

The test survives because `test-build-all.R:38` counts `ValueListDef` nodes, not refs.
Add:

```r
expect_equal(length(xml2::xml_find_all(doc, "//def:ValueListRef", ns)), 2)
```

#### 5. A blank collected unit voids the lab result — and the record vanishes from ADLB

`R/map-lb.R:61-67`

```r
.factor = if_else(!is.na(CONV_FACTOR) &
                    str_to_upper(str_trim(LBORRESU)) == CONV_FROM,
                  CONV_FACTOR, 1),
```

With `LBORRESU` NA, `str_to_upper(str_trim(NA)) == CONV_FROM` is NA, so
`!is.na(CONV_FACTOR) & NA` is NA, so `.factor` is NA, so `LBSTRESN` is NA.

The row still survives into LB, because `LBORRES` is populated — carrying no standard
result and no `LBNRIND`. It then disappears from ADLB entirely, because `derive_adlb()`
works from `lb_results <- lb |> filter(!is.na(LBSTRESN))`.

No validator fires: the `lbstresu-missing` check at `validate-sdtm.R:172` is itself
guarded by `!is.na(LBSTRESN)`.

A site leaving a unit blank is an ordinary real-data event. Wrap the comparison in
`coalesce(..., FALSE)` and add an issue row for "numeric LBORRES with no LBSTRESN".

#### 6. `LBSTRESU` can name a unit the value was never converted into

`R/map-lb.R:61-72`

`.factor` applies only when the collected unit equals `CONV_FROM`, but `LBSTRESU` falls
through to `CONV_TO` whenever `CONV_TO` is non-NA. A third collected unit therefore gives
an unconverted value with a label claiming SI. `LBNRIND` then compares that value against
limits scaled by a different factor, and ADLB inherits both.

Make the unit label follow the factor actually applied, and raise an issue when a
collected unit is neither `CONV_FROM` nor `CONV_TO`.

#### 7. Baseline flags compare dates although times are collected

`R/map-vs.R:84-85`, `R/map-lb.R:110-111`

```r
.eligible = !is.na(VSSTRESN) & !is.na(RFSTDTC) &
  dtc_date(VSDTC) <= dtc_date(RFSTDTC),
```

`VSTIM`/`LBTIM` are collected and ride into `--DTC`, then `dtc_date()` throws the time
away for the comparison. A vital sign taken the same day but *after* first dose is
baseline-eligible, and if it is the last one that day it wins the flag. This is the
standard pre-dose/post-dose baseline error, and it propagates straight into ADVS/ADLB
`BASE`, `CHG` and `PCHG`.

ISO 8601 strings sort correctly, so comparing the full `--DTC` works. If RFSTDTC
genuinely carries no time, say so in the roxygen — as written the code reads like an
oversight rather than a choice.

### (c) Robustness and error handling

#### 8. `as.Date()` called on values that can be reduced-precision DTCs

`R/adam-adsl.R:117` — `pmax(TRTEDT, as.Date(contactdtc), DTHDT, na.rm = TRUE)`
`R/validate-sdtm.R:221` — `mutate(vd = as.Date(str_sub(VSDTC, 1, 10)))`

Both receive values that can legitimately be `"2024-03"` or `"2024"`. Depending on R
version that is a hard error or a silent NA — either way it is the wrong call in a package
that has `dtc_date()` for exactly this purpose. The generator never emits a partial
DSSTDTC or VSDTC, so nothing catches it. Two-character fix in both places.

#### 9. `if (any(x != y))` on columns that can be NA

`R/validate-sdtm.R:96` — `any(df$DOMAIN != d)`
`R/validate-sdtm.R:253` — `any(df$RDOMAIN != rd)`
`R/map-supp.R:150` — `n_occur <- sum(ex$EXOCCUR == "1")` is NA if any `EXOCCUR` is NA, so
the `nrow(parent) != n_occur` guard on the next line throws.

All three raise `missing value where TRUE/FALSE needed` rather than reporting an issue.
A validator that crashes is worse than one that misses. Use `%in%` / `na.rm = TRUE`, and
add a WARN row for the NAs themselves.

#### 10. `generate_rave_extract()` reseeds the caller's global RNG and never restores it

`R/generate-rave-extract.R:1274` — a bare `set.seed(seed)`.

`apply_mh()` already does the save/restore correctly at `:1197` and `:1222`, so the
pattern is in the file; the top-level call just skips it. Any analysis script that
generates an extract mid-session has its RNG silently reset — and `build_all()`'s own
examples call it. Use `on.exit()` restore, or `withr::with_seed()`.

### (b) API design — expensive to change after adoption

These matter more, not less, given the package is meant as an admiral alternative:
third parties writing their own specs and derivation registries are exactly the audience,
and they are the people a signature change would break.

#### 11. Derivations hardcode CRF column names, and `crf_field` on derivation rows is decorative

`R/derivations.R:38-95` reads `data$AEONG`, `data$CMONG`, `data$MHONG`,
`data$DSREAS_DECODE`, `data$Subject`, `data$SiteNumber` directly.

Meanwhile the spec carries a `crf_field` for those rows:

```
"DS", "DSDECOD", "DSREAS_DECODE", "derivation", "dsdecod", NA, NA, NA
```

...which the engine never passes, because `engine.R:51-58` calls `fn(work, spec)` and
nothing else. A study whose ongoing flag is `AECONT` will edit `crf_field`, observe no
effect, and get a `NULL`-length error from inside a derivation.

This bounds "a new study is a spec change" more tightly than the vignette claims. It is
the **cheapest item on this list to fix today and the most expensive after anyone writes
their own registry** — changing the derivation signature later is a breaking change.
Pass `row` (or at least `crf_field`) into the derivation signature now, and document that
derivations must read it rather than naming columns literally.

#### 12. `new_study_spec()` validates shapes but never references

`R/spec.R:89-128` checks required columns, the transform vocabulary and duplicate keys.
It does not check that:

- a `decode` row's `ref` names a codelist that exists in `spec$codelists`
- a `derivation` row's `ref` exists in the registry
- `spec$supp$transform` is one of the three values `supp_transform()` knows
  (`squish`/`yn`/`verbatim`)
- every `spec$variables$domain` is actually buildable

All of those currently surface as an error from deep inside a mapper, halfway through a
build, after the extract has been read. The constructor is the right place and each check
is about three lines. `ct_lookup()` already fails loudly with a good message — hoist that
check to construction time.

#### 13. Clinical thresholds hardcoded inside the validator

`R/validate-adam.R:191`

```r
bad_age <- adsl |> filter(is.na(AGE) | AGE < 18 | AGE > 100)
```

A build-stopping ERROR. A paediatric or elderly-cohort study cannot use this package at
all. Everything else configurable moved into the spec in 0.2.0; this did not.

Same family, lower severity: the AE/DS/DM death-coherence check
(`validate-sdtm.R:346-358`) and `mh-after-first-dose` (`:373-379`) are ERRORs that real
extracts violate routinely for data-management reasons rather than mapping reasons.

Move the age range into `spec$study`; demote the coherence checks to WARN, or make
severity spec-configurable.

#### 14. `RELTYPE` populated on record-level RELREC, and the validator enforces it

`R/helpers-supp.R:102,105` sets `RELTYPE = "ONE"` on every row;
`R/validate-sdtm.R:384-387` refuses anything else.

Per SDTMIG, RELTYPE describes a *dataset*-level relationship; for record-level links keyed
by RELID it is left blank. If that reading holds for your IG version, Pinnacle 21 will
flag every RELREC row and this package's own validator will prevent the fix. Worth
confirming against the IG before changing — but it is compliance-visible either way.

### (d) Test coverage

#### 15. The suite pins behaviour, not correctness, at exactly the hard points

Not a general complaint — a specific list, and the pattern at the end is the real finding:

- No test builds a subject with a missing `TRTEDT` — finding 1 invisible.
- No test feeds a partial `DSSTDTC`/`VSDTC` into ADSL or the validator — finding 8
  invisible.
- No test covers a blank `LBORRESU` on a converted analyte — finding 5 invisible.
- `compute_age()` is tested on two dates the approximation gets right — finding 3
  invisible.
- `test-build-all.R:38` counts `ValueListDef`, not `ValueListRef` — finding 4 invisible.
- `ANRIND` is never tested with `ANRLO` present and `ANRHI` missing. `adam-advs.R:85-90`
  guards only `ANRLO`, so `AVAL > NA` is NA and everything falls through to `"NORMAL"`.
- `PARAM = str_c(VSTEST, " (", VSSTRESU, ")")` is never tested with a missing unit.
  `str_c` propagates NA, so a required ADaM variable silently becomes NA.

**Every one of these needs input the seeded generator never produces.** The regression
suite and the generator share a blind spot by construction, and freezing reference `.rds`
files makes that blind spot permanent.

A `test-edge-cases.R` that builds five-row tibbles by hand and calls the derivation
functions **directly, never through `build_all()`**, closes most of it in an afternoon.

### Deliberately not raised

- **Style.** `.lintr` is configured, CI runs `lint_package()` with `LINTR_ERROR_ON_LINT`,
  and it is green. Nothing to add that lintr is not already enforcing.
- **Documentation** is unusually good. Two exceptions: `vignettes/design.Rmd` sets
  `eval = FALSE` globally, so none of its code is ever executed or checked and it can rot
  silently; and there is no pkgdown config despite three badges and two vignettes that
  would carry a site well.
- **Below the bar, but noted:** `str_flatten_comma(rngs, "; ")` at `define-xml.R:236`
  passes a separator into an argument named `last`; `map_suppae`'s error message prints a
  negative count if the join fans out; `read_clinical_view` drops `RecordActive` NA rows
  silently along with the zeros; `PCHG` has no zero-`BASE` guard (harmless for VS,
  reachable for LB); `validate_adam`'s `bad_range` checks `xor(is.na(ANRLO.x), ...)` with
  no ANRHI equivalent; `map_sv` takes `first(TargetDays)` without ordering; `.lb_blind` at
  `validate-adam.R:595` is created and never used; the `constant` transform always yields
  character.

## Where pharmaverse and CRAN overlap

Framed for a package that is *competing with* admiral rather than adopting it.

### admiral — as benchmark and test oracle, not as a dependency

The functional overlap is close enough to be useful:

| edc2cdisc | admiral counterpart |
|---|---|
| `derive_dy_d()` / `derive_dy()` | `derive_vars_dy()` |
| `impute_dtc()` | `derive_vars_dt(highest_imputation = )` — same `""`/`"D"`/`"M"` flag convention |
| `derive_seq()` | `derive_var_obs_number()` |
| TRTEMFL block in `derive_adae()` | `derive_var_trtemfl()` — handles missing TRTEDT correctly, and takes an `end_window` |
| BASE / CHG / PCHG / ABLFL | `derive_var_base()`, `derive_var_chg()`, `derive_var_pchg()`, `derive_var_extreme_flag()` |

**Recommendation: put admiral in `Suggests` and use it in tests only, as a differential
oracle.** For each helper, build a small input frame, run both implementations, and assert
they agree — or assert they differ *in the documented way*, with the divergence written
down. That does three things a dependency would not:

1. It would have caught finding 1 the day it was written.
2. It converts "my rule" into "my rule, and here is exactly how it differs from the
   community's rule" — which is the entire value proposition of an alternative, and the
   thing a sponsor's QC will ask about first.
3. It costs nothing at run time and does not compromise the independence that is the point
   of the package.

Where you deliberately diverge (e.g. no grace window on TRTEMFL, first-of-month
imputation), the divergence should be a documented, tested claim rather than an
implementation detail.

### metacore + metatools + xportr — the one swap actually worth making

`xportr` already does what `write_sdtm()` does: name/label/length/type checks against a
metadata spec, then `write_xpt()`. `metacore` is a mature answer to `study_spec` plus
define.xml. Since `build_define_xml()` is explicitly a stub (and finding 4 shows the cost
of maintaining a hand-rolled one), this pair would replace both it and `write_sdtm()` with
submission-grade output.

This is the biggest single leverage swap available, and — unlike admiral — it does not
touch the derivation layer where the package is making its argument. If you make one
swap, make it this one.

### clock or lubridate

For finding 3. `clock::date_count_between()` is the more precise tool;
`lubridate::time_length(interval(b, r), "years")` floored also works.

### pharmaversesdtm

A second source of test inputs, not a replacement for the generator — yours starts one
layer earlier, at the EDC extract, which is the whole point of it.

### Not worth swapping

`check_ct()` (loud-failure-on-unmapped is better than a generic recode), the issue-tibble
validator pattern, `make_supp()`.
