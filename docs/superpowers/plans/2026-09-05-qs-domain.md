# QS (Questionnaires) Domain Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. This plan is written for **unattended overnight execution**: never push, never merge, commit per task, keep the full suite green at every commit, and on any BLOCKED finding stop cleanly with a written report instead of improvising.

**Goal:** Add the SDTM QS domain: a new scheduled `QS` CRF form in the generator, a `map_qs()` findings mapper, validation, define.xml coverage, frozen references and docs.

**Architecture:** QS is a findings domain in the VS/LB family: wide CRF form pivoted through `spec$tests` rows into one SDTM row per item. All QS content is deterministic (config-driven messiness, index-arithmetic values, zero RNG draws) so every existing extract byte and reference stays frozen.

**Tech Stack:** R package; dplyr/stringr/labelled; testthat; haven XPT v5; xml2.

**Spec:** `docs/superpowers/specs/2026-09-05-qs-domain-design.md` — read it first; it records the design decisions and the file:line anchors from the architecture survey.

    }
